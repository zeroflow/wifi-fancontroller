The Rev 3.x series is the latest generation of the WiFi Fan Controller. All 3.1, 3.2, and 3.3 boards share identical firmware and pinout -- differences between sub-revisions are hardware-only improvements.

Key features over Rev 3.0: RGB status LEDs (SK6805) for board status and per-fan visual feedback.

## Specifications

- **MCU:** ESP32S2-Mini-2
- **Board platform:** esp32-s2-saola-1
- **Power:** external 12V DC SELV supply, not included (5.5x2.1mm barrel jack, centre positive, 12V DC ±5%)
- **Max total input current:** 2.5A (set by the DC barrel jack -- applies to the sum of all fans plus board electronics, not per fan header; size your supply to the combined draw of the fans you connect). See [Safety and Compliance](/reference/compliance/).
- **Flashing:** USB-C port
- **Fan outputs:** 4x PWM headers with signal buffering
- **Status LEDs:** SK6805 RGB LEDs for board status and each fan connector
- **Sensor:** HDC1080 Temperature and Humidity
- **Buttons:** Reset, Boot, 3x User
- **Expansion:** QWIIC I2C, I2C port (100mil), NeoPixel port (5V, max 2A), SMD expansion header

<Aside type="note" title="NeoPixel framework requirement">
The NeoPixel port on GPIO42 requires the `arduino` framework. The `esp32_rmt_led_strip` platform used for this pin does not work reliably with `esp-idf` on the ESP32-S2.
</Aside>

<Aside type="caution" title="USB not working?">
The ESP32-S2 has known USB reliability issues. If the flash button doesn't detect your board:
1. Try a different USB cable (data cable, not charge-only)
2. Hold BOOT button while plugging in USB
3. Use [ESPWEBTOOL](https://esptool.spacehuhn.com/) as an alternative web flasher (flash binary at address 0x0)
4. As last resort, use `esptool.py` CLI: `esptool.py --chip esp32s2 write_flash 0x0 firmware.bin`

Download prebuilt binaries: [Rev 3.1](/firmware/fancontroller-r3-1-esp32s2.factory.bin) / [Rev 3.2](/firmware/fancontroller-r3-2-esp32s2.factory.bin) / [Rev 3.3](/firmware/fancontroller-r3-3-esp32s2.factory.bin)
</Aside>

<Aside type="caution" title="USB-C is for flashing only">
The USB-C port provides power to the ESP32-S2 microcontroller only. It cannot power the fans. Fans require an external 12V DC power supply connected to the DC input jack (5.5x2.1mm).
</Aside>

## Hardware Self-Test Firmware

Every board is tested with a QC firmware before it ships, and that same image is available here. It is a diagnostic build, not a usable controller firmware: it takes no WiFi credentials, joins no network and exposes nothing to Home Assistant. It exercises the hardware and reports the result through the onboard LEDs, so you can tell a genuine hardware fault from a configuration problem without attaching a serial console. Flash it if a fan channel, the sensor or a button seems dead and you want a second opinion before opening an issue.

What it checks, and how to read it:

- **Fan channels.** All four PWM outputs run at 1000 Hz and each tach input reads that signal back. The LED next to a fan header turns green as soon as its channel reports a signal and stays red if nothing comes back.
- **Temperature and humidity sensor.** The board status LED shows dim purple on every valid HDC1080 reading, refreshed every 5 seconds. A status LED that stays dark means the sensor is not answering on the I2C bus.
- **User buttons.** Hold USR1 for a red status LED, USR2 for green, USR3 for blue. The LED goes dark on release and returns to the purple heartbeat.

<FlashButton manifest="/firmware/fancontroller-qc-r3-3.manifest.json" label="Flash QC Test Firmware (Rev 3.1 / 3.2 / 3.3)" />

The [config is in the repository](https://github.com/zeroflow/wifi-fancontroller/blob/main/fancontroller-rev3.3-esp32s2.qc.yaml) if you would rather read what it does before flashing it.

<Aside type="caution" title="This replaces the firmware on the board">
Flashing the QC image overwrites whatever is currently on the board, including your ESPHome config and its stored WiFi credentials. When you are done testing, flash the factory firmware above or your own ESPHome build to get back. Note also that the QC image drives the fans at 50% with a 1000 Hz test frequency instead of the usual 25 kHz, so fans may whine or run at an odd speed while it is loaded. That is the test, not a fault.
</Aside>

## Serial Flashing Header (TX/RX)

In addition to the USB-C port, the board exposes the ESP32-S2 UART0 on a serial header for flashing and serial logs. This is the fallback path when USB-C is not detected (see the USB troubleshooting note above) and the channel ESPHome's `logger` uses by default.

| Signal | Pin | Description |
|--------|-----|-------------|
| 3.3V | 3.3V |              |
| TX | GPIO43 | UART0 transmit (U0TXD), board to host |
| RX | GPIO44 | UART0 receive (U0RXD), host to board |
| GND | GND | Common ground (required for serial) |

Connect a 3.3V USB-to-serial adapter (TX to RX, RX to TX, GND to GND). To enter the bootloader for flashing, hold BOOT (GPIO0) while resetting the board.

<Aside type="caution" title="3.3V logic only">
The ESP32-S2 UART pins are 3.3V. Do not connect a 5V serial adapter directly to TX/RX.
</Aside>

## Qwiic Connector

The board offers a Qwiic connector (standard JST-SH 4-pin, 1mm pitch) for solderless I2C expansion. It shares the **same I2C bus** as the 100mil I2C extension port and the onboard HDC1080 sensor, so addresses must not conflict across both ports.

| Nr. | Pin | Description |
|-----|-----|-------------|
| 1 | GND | Black wire |
| 2 | +3V3 | Red wire |
| 3 | SDA | GPIO 33, blue wire, 4.7k Pull-Up |
| 4 | SCL | GPIO 34, yellow wire, 4.7k Pull-Up |

<Aside type="note" title="Shared I2C bus">
The Qwiic port, the 100mil I2C extension port, and the onboard HDC1080 temperature/humidity sensor are all on the same I2C bus (GPIO33 SDA / GPIO34 SCL). Devices on any of these connectors share that bus.
</Aside>

## Revision History

All Rev 3.1, 3.2, and 3.3 boards share identical firmware and pinout. The differences between sub-revisions are hardware-only improvements:

| Revision | Changes |
|----------|---------|
| Rev 3.1 | Added RGB status LEDs (SK6805) for board + per-fan indication |
| Rev 3.2 | Improved USB-C fuse for better overcurrent protection |
| Rev 3.3 | Open-drain fan outputs, optimized component selection, enhanced power supply stability |
